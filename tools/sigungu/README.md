# 시군구 정적 데이터 생성기 (SPEC-0015)

`V45__load_sigungu.sql`은 **손으로 쓰지 않고 이 스크립트로 생성했다.** 경계가 바뀌면
파일을 고치는 것이 아니라 여기서 다시 만들어 새 `V{n}` 마이그레이션을 추가한다.

## 입력

| 파일 | 출처 |
|---|---|
| `kto_sigungu_codes.tsv` | KTO 공식 시군구 코드 파일 252행. **명칭·시도명의 권위는 이쪽이다** |
| `names.py` | EN·JA·ZH 명칭 표. 한자 독음 기반 생성물이며 사용자 검수를 1회 거쳤다 |
| 행정동 경계 GeoJSON | `vuski/admdongkor` `ver20240401` (공공누리, 통계청 원자료 가공) |

## 경계 버전을 `ver20240401`로 고정한 이유

**KTO 코드 파일 252건과 코드 집합이 정확히 일치하는 유일한 버전이다.** 다른 버전은 어긋난다.

- `ver20230701` — 전북이 아직 `45`(전라북도)이고 부천시가 일반구로 나뉘기 전이라 18건 어긋남
- `ver20260701` — 전남·광주 통합(`12`), 인천 제물포/영종/서해/검단구, 화성시 일반구 신설이
  반영되어 KTO가 아직 쓰지 않는 코드가 31건 섞임

즉 **최신본을 쓰면 안 된다.** KTO가 코드 체계를 갱신하면 그때 맞는 버전으로 올린다.

## 산출 규칙

1. 행정동 3,553건을 시군구 코드(`sgg`)로 합친다(dissolve) → 252건
2. `0.0001`도(약 11m)로 단순화한다. 원본 11MB → 4.9MB. 시군구 규모에서는 지도 표시·공간
   조인에 영향이 없다
3. 대표 좌표는 **단순화된 도형에서** 뽑는다 — 저장된 `boundary`와 `center`가 반드시 같은
   도형에서 나와야 하기 때문이다
4. 대표점은 **면적이 가장 큰 조각을 고른 뒤** 그 위에서 구한다(설계 §1.2). MultiPolygon
   전체에 대표점을 구하면 섬이 많은 지역에서 본토가 아닌 작은 섬에 찍힌다
   (신안군 191조각 · 완도군 103조각 · 여수시 91조각 · 옹진군 77조각)

생성 시 다음을 단언(assert)한다 — 하나라도 깨지면 스크립트가 멈춘다.

- 코드 집합이 KTO 252건과 정확히 일치
- 전부 valid `MultiPolygon`
- 대표점이 최대 조각 **내부**이고 도형 전체 내부 (R3)
- 좌표가 위경도 유효 범위 안 (R3)

## ZH는 번체다

`name_zh`·`province_name_zh`는 **번체(正體)**다. 중국 본토는 서비스 대상이 아니고(스토어 등재
불가) 실제 대상이 대만·홍콩이기 때문이다 — 근거는 CLAUDE.md에 있다.

`name_ja`는 일본 신자체라 **의도적으로 다르다.** 동래구가 ja `東莱区` · zh `東萊區`인 것이
정상이며, 한쪽을 다른 쪽에 복사하면 안 된다. 재생성할 때 zh에 `区`(간체)가 하나라도 들어가면
결함이다.

## 알아둘 것

**옹진군의 대표점은 백령도에 찍힌다.** 옹진군에서 면적이 가장 큰 섬이 실제로 백령도라
그렇다. 오류가 아니다 — 규칙대로 동작한 결과이며, 육지 위 점임은 보장된다.
