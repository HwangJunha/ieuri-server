# SPEC-0029 클라이언트 대응 요청 — 장소가 활성 언어 단위로 갈립니다

> 서버 이슈 [#96](https://github.com/HwangJunha/ieuri/issues/96) · PR [#97](https://github.com/HwangJunha/ieuri/pull/97) · 스펙 `Specs/SPEC-0029/`
> 클라이언트 이슈 [#69](https://github.com/HwangJunha/ieuri/issues/69)

## 한 줄 요약

**spot이 원문 있는 언어에서만 보입니다.** 기계번역을 걷어냈고, 그래서 언어 폴백도 없앴습니다. 좋아요·글·질문도 같은 축을 따릅니다.

**서버와 동시 배포해야 합니다** — 아래 인자 삭제 때문에 순서가 아니라 동시입니다.

---

## 1. 먼저 — SPEC-0019를 되돌립니다

`problem/SPEC-0019-client-prompt.md`에서 안내했던 것 중 둘이 뒤집힙니다.

| SPEC-0019에서 | SPEC-0029에서 |
|---|---|
| `hasOrigin` 인자 도입 (원문/번역본 선택) | **삭제** — 고를 대상이 없어졌습니다 |
| 좋아요가 언어 무관하게 통합 | **언어별로 분리** |
| "id는 언어와 무관하다" | id는 여전히 언어 무관, **그러나 열람 가능 여부는 아닙니다** |

마지막 항목이 가장 중요합니다. 아래 3절에서 자세히 씁니다.

## 2. BREAKING — `hasOrigin` 인자 삭제 (4곳)

```
spots(hasOrigin:)            ← 삭제
popularSpots(hasOrigin:)     ← 삭제
ongoingFestivals(hasOrigin:) ← 삭제
mapViewport(hasOrigin:)      ← 삭제
```

**이 인자를 보내면 쿼리가 실패합니다.** 서버가 배포되는 순간부터입니다.

기계번역을 없애서 이제 모든 결과가 활성 언어의 원문입니다. "원문만 볼지" 고를 이유가 사라졌습니다.

### 함께 사라지는 것 — 2단 조회

`lib/common/pagination/origin_fill.dart`와 그 호출부를 **전부 제거**해 주세요.

이 헬퍼는 "원문 먼저 채우고 모자라면 번역본으로 보충"하는 용도였습니다. 이제 서버가 한 번에 활성 언어 원문만 주므로 존재 이유가 없습니다.

- **홈**: 섹션당 2회 → **1회**
- **지도**: `map_screen.dart`의 `mapViewport` 2회 호출 → **1회** (`:345`·`:366` 부근)
- **축제**: `happening_now_section.dart` 2단 조회 → 1회

## 3. 가장 중요 — 저장해 둔 spot id는 안전하지 않습니다

**id 자체는 여전히 언어와 무관합니다.** 같은 장소는 어느 언어에서든 같은 id입니다. 그건 안 바뀌었습니다.

**바뀐 것은 "그 id를 지금 열 수 있는가"입니다.**

```
목록에서 방금 받은 id  → 안전합니다 (그 목록이 이미 활성 언어로 걸러졌으니까)
저장해 뒀다가 쓰는 id  → 안전하지 않습니다 (그 사이 언어를 바꿨다면)
```

서버 스키마 8곳에서 "이 id는 언제나 `spotDetail(id:)`에 넘길 수 있다"는 **무조건적 보장을 철회**했습니다. 클라이언트 모델 2곳도 같은 주장을 하고 있으니 함께 고쳐 주세요:

- `lib/common/model/post_spot.dart:8`
- `lib/common/model/spot_qa_origin.dart:14-15`

주석을 지우는 게 아니라 **구분을 담아** 다시 쓰는 것이 요점입니다. 다음 사람이 "저장해 뒀다 써도 된다"고 읽지 않도록요.

## 4. 새 오류 코드 — `SPOT_NOT_FOUND_IN_LOCALE`

기존 `SPOT_NOT_FOUND`와 **반드시 구분해 주세요.** 사용자에게 다른 안내를 해야 합니다.

| 코드 | 뜻 | 안내 |
|---|---|---|
| `SPOT_NOT_FOUND` | 그런 장소가 없음 | "존재하지 않는 장소입니다" |
| `SPOT_NOT_FOUND_IN_LOCALE` | 있지만 **이 언어에서는 볼 수 없음** | "이 언어에서는 볼 수 없는 장소입니다" + 홈 복귀 |

두 번째는 **언어를 바꾸면 볼 수 있는 장소**라는 게 핵심입니다. "없다"고 안내하면 사용자가 오해합니다.

### 어디로 오나

**최상위 `errors[]`** — `spotDetail`, `spotQuestions`, `posts`
**payload `userErrors`** — `createPost`, `editPost`, `createSpotQuestion`

`reactToSpot`은 `userErrors`로 `SPOT_NOT_FOUND` 또는 `SPOT_NOT_FOUND_IN_LOCALE`이 옵니다.

### 정상 경로에서는 안 나옵니다

목록·칩·마커가 전부 활성 언어로 걸러지므로, 이 오류에 도달하는 건 **우회 진입뿐**입니다 — 딥링크, 푸시 페이로드, 복원된 초안, 언어를 바꾸기 전에 열려 있던 화면. 마지막 방어선으로만 두시면 됩니다.

## 5. 결과 집합이 좁아집니다 (인자·응답 형태는 그대로)

조회 8종이 같은 인자를 받고 같은 모양으로 답하는데 **반환 행만 줄어듭니다.**

- 홈·지도·둘러보기·검색·좋아요 목록·인기·축제
- 활성 언어에 원문이 없는 spot은 그냥 안 나옵니다 (오류 아님)

**`popularSpots`는 별개 변경이 하나 더 있습니다.** 최소 좋아요 수가 10에서 **5로 낮아졌습니다.** 언어 축 분리로 좋아요가 줄어드는 것과 무관한 독립 변경이라, 같은 데이터에서도 이전에 안 보이던 spot이 들어옵니다.

## 6. 좋아요가 언어별로 갈립니다

```
EN에서 좋아요 5개 → JA로 변경 → 좋아요 목록에 0개
                              → EN으로 되돌리면 5개 복귀
```

**삭제된 게 아닙니다.** 그 언어로 돌아가면 그대로 있습니다. 사용자에게 "사라졌다"고 느껴지지 않도록 안내가 필요할 수 있습니다 — 판단은 맡기겠습니다.

집계도 언어별입니다. `likeCount`는 활성 언어에서 누른 것만 셉니다.

## 7. 글·질문 목록에서 일부가 빠집니다

활성 언어에서 해소되지 않는 spot이 붙은 글·질문은 **목록에서 빠집니다.** 오류가 아니라 그냥 없습니다.

- spot이 **안 붙은** 글은 언어와 무관하게 나옵니다
- `posts(catalogId:)`로 좁혀 조회할 때 그 카탈로그가 활성 언어에 없으면 **빈 목록이 아니라 `SPOT_NOT_FOUND_IN_LOCALE`** 입니다 (규약 변경)
- `PostSpot.title`이 한국어 고정에서 **활성 언어 해소**로 바뀝니다

### 해소되지 않는 spot 참조는 탭 불가로

세 곳의 동작이 다릅니다. 스키마의 nullable 여부가 다르기 때문입니다.

| 위치 | 타입 | 해소 안 될 때 |
|---|---|---|
| `Post.spot` | `PostSpot` (nullable) | **null**로 옵니다 → 칩을 그리지 않거나 탭 불가로 |
| `SpotQuestion.spot` | `PostSpot!` (non-null) | 애초에 **그 질문이 목록에 안 나옵니다** — null이 올 일이 없습니다 |
| `Message.spotQaOrigin` | nullable | 인용 스냅샷이라 **값은 남아 있지만** 그 `catalogId`가 지금 언어에서 안 열릴 수 있습니다 → 탭 불가로 |

DM 인용이 특히 주의할 곳입니다. `spotTitle`은 **인용 시점에 발신자 언어로 굳은 스냅샷**이라 값이 항상 있습니다. 하지만 `catalogId`를 `spotDetail(id:)`에 넘기면 `SPOT_NOT_FOUND_IN_LOCALE`이 날 수 있습니다 — 제목이 보인다고 열리는 건 아닙니다.

## 8. 언어 변경 시 전역 무효화가 필요합니다

`lib/domain/settings/view/preferences_screen.dart:110-120`에서 언어를 바꿀 때, **spot id를 들고 있는 상태를 전부 비워야** 합니다.

- spot·좋아요·커뮤니티 관련 프로바이더
- 누적된 지도 마커
- 저장된 초안의 `spotId` (**본문·사진은 보존**하고 spotId만 비우기)
- spot 재시도 예산
- GraphQL 캐시 — 같은 쿼리·변수라도 언어가 다르면 **다른 항목**이어야 합니다

### 로컬 저장소도 언어로 분리

- 최근 검색어 — 저장 키에 언어 포함
- 카테고리 선택 상태 — 새 언어에 없는 코드는 버리기

## 9. 서버 배포 상태

이미 적용 완료입니다 (2026-08-20):

- 마이그레이션 V70~V73 성공
- **spot 데이터 전량 초기화됨** — spot·카탈로그·번역·좋아요·글-장소 연결이 전부 0
- 사용자 계정과 글 본문은 보존
- 검색 노드 복제 정상

**주의**: 재적재 배치가 아직 돌지 않아 지금은 모든 spot 조회가 빈 결과입니다. 배치 1회 완료 후 데이터가 쌓입니다.

**그리고 하나 더** — 배정 배치가 처음 돌기 전까지는 **spot이 붙은 글·질문도 목록에서 빠집니다.** 커뮤니티가 "이 카탈로그가 어느 언어에서 보이나"의 사본을 갖는데, 그 사본이 배치 이벤트로 채워지기 때문입니다. 배치가 돌면 정상화됩니다.

## 10. 확인 부탁

- `hasOrigin`을 보내는 곳이 남아 있지 않은지 (**서버 배포 시점에 즉시 실패**합니다)
- `origin_fill.dart`와 호출부가 전부 제거됐는지
- 지도가 1회 호출로 바뀌었는지
- `SPOT_NOT_FOUND`와 `SPOT_NOT_FOUND_IN_LOCALE`이 다르게 안내되는지
- 언어 변경 시 spot 관련 상태가 전부 비워지는지
- 모델 2곳의 "id는 항상 안전하다" 주석이 철회됐는지
