# 이으리(ieuri) 회원 상태 관리 명세 — Step 3: 탈퇴 / 정지(서버)

> 기능을 쪼개서 단계적으로 진행합니다. 이 문서는 **회원 탈퇴(본인)·정지(관리자)·복구 서버 로직**을 다룹니다.
> 회원가입(Step 1)·로그인(Step 2)은 별도 명세에서 완료되었습니다.

---

## 범위 (Scope)

- **이번 스텝**: 회원 **탈퇴(self-service) = 데이터 완전 삭제(hard delete)** + 토큰 폐기 · 회원 **정지/복구(관리자)** · 상태에 따른 로그인 차단 · **access token 인증 필터**(탈퇴 본인 확인에 필요) · Apple 토큰 revoke(추상화).
- **다음 스텝(별도)**: 본격 RBAC/관리자 권한, 관리자 UI, 실제 Apple revoke 자격증명 연동.

---

## 전제 (기존 스텝에서 확보된 것)

- `member.status` 컬럼은 Step 1에서 확보됨. Step 1의 `MemberStatus` enum과 `ck_member_status` 제약에는 `WITHDRAWN`이 포함돼 있으나 **어떤 row도 사용하지 않으므로**(탈퇴=행 삭제), 이 스텝에서 **제거한다**: enum에서 `WITHDRAWN` 삭제 + V7에서 제약을 `('ACTIVE','SUSPENDED')`로 조임. 이후 상태값은 `ACTIVE`/`SUSPENDED` 둘뿐.
- `member`의 소유 테이블: `member_profile`, `member_terms_agreement`, `email_verification` (모두 `member(id)` FK). `member_audit_log`는 `member_id`를 **FK 없는 평문 컬럼**으로 보관.
- 로그인(Step 2)은 `ACTIVE`가 아니면 거부(`InactiveMemberException`). refresh 저장소에 `revokeAllByMember`가 있어 회원 전체 토큰 폐기 가능.
- 토큰은 In-memory(추후 Redis/Valkey). accessToken 5분, refreshToken 30일.

---

## 정책 결정사항 (Decisions)

- **탈퇴는 본인만**(self-service). 인증된 회원 자신만 탈퇴하며, 요청에 member_id를 받지 않는다(토큰의 신원으로 판단).
- **탈퇴 = 즉시 완전 삭제(hard delete)**. 유예기간 없이 **회원 및 소유 데이터 행을 삭제**한다: `member` + `member_profile` + `member_terms_agreement` + `email_verification`. 익명화(soft)가 아니라 **레코드 삭제**다. (개인정보보호법 §21 "지체 없이 파기"를 레코드 삭제로 이행)
- **감사 로그만 보존**: `member_audit_log`는 개인정보가 아닌 `member_id`(내부 식별자) + 이벤트 유형만 담으므로 **삭제하지 않고 보존**(보안·감사 추적용). 탈퇴 이벤트도 PII 없이 기록.
- **재가입은 자연 허용**: 행이 삭제되면 `(provider, provider_user_id)` 유니크가 자동 해제되므로, 같은 SNS 계정 재가입은 Step 1을 그대로 타 **새 회원**으로 생성된다. (익명화 tombstone 불필요)
- **정지/복구는 관리자 작업**. 본격 RBAC는 다음 스텝이므로 이번엔 **최소 admin 가드**(설정 기반 관리자 키)로만 보호한다.
- **정지 = 상태만 변경, 개인정보 보존**. `status=SUSPENDED` + 사유(`reason`) + 선택적 만료일(`suspended_until`). 만료일이 지난 정지는 **로그인 시점에 자동 복구**(지연 해제). 만료일이 없으면 무기한.
- **정지 계정은 자동 파기하지 않는다**: 개인정보 유효기간제(장기 미이용자 1년 파기·분리보관, 정보통신망법 §39-6)는 **2023-09-15 폐지**되어 정지/휴면 개인정보의 **법정 자동 파기 의무가 없고** 처리 정책은 사업자 자율이다. **파기(삭제)는 탈퇴 시에만** 수행한다.
- **토큰 무효화**: 탈퇴·정지 즉시 `revokeAllByMember`로 refresh 전량 폐기. accessToken은 5분 자연 만료(즉시 무효화는 범위 밖).
- **access token 인증**: 탈퇴 본인 확인을 위해 이번 스텝에 **accessToken 검증 Security 필터**를 도입한다(요청의 Bearer 토큰 → 인증 주체 memberId). 이후 인증 필요한 모든 기능의 토대.
- **Apple 토큰 revoke**: 애플 정책상 계정 삭제 시 토큰 폐기 필요. `SnsTokenRevokerPort`로 추상화, 지금은 dev 구현(실제 revoke는 자격증명 준비 후).
- **이벤트**: 탈퇴/정지/복구 시 도메인 이벤트 발행 → 추후 크로스도메인 정리(커뮤니티/커머스) 트리거. 이번 스텝은 이벤트 발행·감사 기록까지만.

## 포함 기능 (In Scope)

1. 탈퇴(본인) — **회원+소유 데이터 행 삭제** + refresh 전량 폐기 + Apple revoke(해당 시) + 감사 기록(PII 제외)
2. 정지(관리자) — 상태 변경 + 사유/만료일 저장 + refresh 전량 폐기 + 감사 기록
3. 복구(관리자) — SUSPENDED → ACTIVE
4. 기간제 정지 자동 해제 — 로그인 시 `suspended_until` 경과 시 자동 복구
5. 상태별 로그인 차단 — SUSPENDED(사유 안내). 삭제된 회원은 미조회 → 재가입 유도(`MEMBER_NOT_FOUND`, Step 2)
6. accessToken 인증 필터 — 인증 주체(memberId) 확립
7. 최소 admin 가드 — 정지/복구 보호(임시)

---

## 제외 기능 (Out of Scope — 다음 스텝)

1. 본격 RBAC/권한 모델, 관리자 계정 체계
2. 크로스도메인 데이터 실제 삭제(커뮤니티 글/커머스 주문 등) — 이벤트만 발행
3. 실제 Apple revoke 자격증명·네트워크 연동(지금은 dev 추상화)
4. accessToken 즉시 무효화(블랙리스트) — 5분 만료로 대체
5. 관리자/앱 UI

## 필수 규칙 (Invariants)

상태 머신(탈퇴는 행 삭제라 상태로 남지 않음):

```
ACTIVE    --정지(관리자)-->      SUSPENDED
SUSPENDED --복구(관리자/자동)-->  ACTIVE
ACTIVE/SUSPENDED --탈퇴(본인)-->  (행 삭제 — 종단)
```

1. **탈퇴는 회원+소유 데이터 행 삭제**(종단). 삭제 후 재활성 불가. 같은 SNS 재가입은 **새 회원**으로만.
2. 탈퇴는 **본인만**, 정지/복구는 **관리자만**.
3. 탈퇴·정지 시 해당 회원 refresh는 **전량 폐기**된다.
4. 탈퇴 시 개인정보(및 소유 데이터)는 **삭제**한다. 단, `member_audit_log`(비-PII)는 보존.
5. 정지는 개인정보를 삭제하지 않는다(상태 변경만).
6. `reactivate`(복구)는 **SUSPENDED에서만** 가능.
7. 정지 중 로그인은 거부하되, **만료일이 지난 기간제 정지는 자동 복구** 후 허용.
8. 상태 전이(정지/복구) 업무 불변식은 **도메인(Member)** 에서 강제한다.

## 흐름 (Flows)

### 1) 탈퇴 (본인)
1. `withdrawMember` — accessToken으로 인증된 memberId 확보(입력에 member_id 없음).
2. 회원 존재 확인. Apple provider면 `SnsTokenRevokerPort.revoke` 시도.
3. **한 트랜잭션에서 소유 데이터 삭제 후 회원 삭제**: `email_verification` → `member_terms_agreement` → `member_profile` → `member` (FK 자식부터). refresh 전량 폐기(`revokeAllByMember`).
4. 감사 기록(`MEMBER_WITHDRAWN`, PII 없이 memberId+시각) + `MemberWithdrawn` 이벤트 발행.

> FK 삭제는 앱 레이어에서 자식→부모 순서로 명시 삭제(또는 마이그레이션에서 `ON DELETE CASCADE` 부여). `member_audit_log`는 FK가 없어 삭제와 무관하게 보존된다.

### 2) 정지 (관리자)
1. `suspendMember(memberId, reason, until?)` — admin 가드 통과.
2. 도메인 전이: `Member.suspend(reason, until, now)` (ACTIVE/SUSPENDED에서 사유·기간 설정/갱신).
3. refresh 전량 폐기. 감사 기록(`MEMBER_SUSPENDED`) + `MemberSuspended` 이벤트.

### 3) 복구 (관리자 / 자동)
1. `reactivateMember(memberId)` (admin) 또는 로그인 시 만료 정지 자동 해제.
2. 도메인 전이: `Member.reactivate(now)` (SUSPENDED → ACTIVE). 감사 기록(`MEMBER_REACTIVATED`).

### 로그인 상호작용 (Step 2 보강)
- SUSPENDED + `suspended_until`이 지났으면 → 자동 복구 후 로그인 허용.
- SUSPENDED(무기한 또는 미도래) → 거부 + 사유 안내.
- 삭제된(탈퇴) 회원 → 미조회 → `MEMBER_NOT_FOUND`(재가입 유도).

## 스키마 변경 (Flyway) — 예: `V7__add_member_suspension_columns.sql`

`member`에 **정지** 메타데이터 컬럼만 추가한다. 탈퇴는 행 삭제라 별도 컬럼이 필요 없다(`withdrawn_at` 불필요).

- `suspended_at TIMESTAMPTZ NULL`
- `suspended_until TIMESTAMPTZ NULL`
- `suspension_reason VARCHAR(500) NULL`
- **`ck_member_status` 제약을 `('ACTIVE','SUSPENDED')`로 조임** (기존 제약 DROP 후 재생성). `MemberStatus` enum에서도 `WITHDRAWN` 값을 제거한다. (V1은 immutable이므로 이 변경은 V7에서 수행)

> (선택) 소유 테이블 FK에 `ON DELETE CASCADE`를 부여하는 마이그레이션을 함께 둘 수 있다. 채택 시 앱은 `member`만 삭제하면 자식이 연쇄 삭제된다. 미채택 시 앱이 자식→부모 순서로 삭제한다. **감사 로그(`member_audit_log`)는 FK가 없어 어느 경우든 보존.**
> 상태 전이 이력은 별도 테이블 없이 `member_audit_log`(jsonb)로 남긴다.

## 탈퇴 삭제 범위 & 재가입 상세

- **삭제 대상(행 삭제)**: `member`, `member_profile`, `member_terms_agreement`, `email_verification`.
- **보존 대상**: `member_audit_log`(비-PII: 내부 `member_id` + 이벤트 유형/시각). 개인 식별자·이메일 등은 담지 않는다.
- **재가입**: 행이 삭제되어 `(provider, provider_user_id)` 유니크가 해제되므로 동일 SNS 재가입은 Step 1을 그대로 타 **새 회원**(새 id)으로 생성. member id는 IDENTITY라 재사용되지 않아 과거 audit_log와 충돌 없음.
- **동의 이력**: 회원과 함께 삭제된다(완전 파기 원칙). 향후 "동의 획득 증빙 보존"이 법적으로 요구되면 별도 보존 설계 재검토.

## 인증 / 권한

- **accessToken 인증 필터**: Spring Security 필터에서 `Authorization: Bearer <access>` 검증(서명·만료·`typ=access`) → 인증 주체 memberId 설정. `TokenProviderPort`에 `parseAccessToken` 추가. 인증 실패는 401.
  - 공개 엔드포인트(회원가입/로그인/refresh)는 permit 유지, 탈퇴 등은 인증 필요.
- **admin 가드(임시)**: 정지/복구는 설정 기반 관리자 키(헤더)로 보호. **본격 RBAC는 다음 스텝**이며, 이 가드는 인터페이스로 두어 교체 가능하게 한다.

## 헥사고날 배치

- **domain**: `Member`에 **정지/복구 상태 전이**(`suspend`/`reactivate` + 불변식)와 로딩용 `reconstitute` 추가. 정지 메타(suspendedAt/suspendedUntil/reason)를 값으로 보유. (탈퇴는 상태 전이가 아니라 삭제이므로 도메인은 "삭제 가능 여부" 정도만 관여하고, 실제 삭제는 애플리케이션이 오케스트레이션.)
- **application**: `WithdrawMemberUseCase`/`SuspendMemberUseCase`/`ReactivateMemberUseCase` + 커맨드/핸들러. 아웃바운드 포트: 회원 로드/삭제/저장 포트 확장(`deleteMemberCascade` 등), `RefreshTokenStorePort`(재사용), `SnsTokenRevokerPort`(신규), 현재 인증 주체 제공(`AuthenticatedMemberProvider`).
- **infrastructure**: JWT 인증 필터, admin 가드, `SnsTokenRevoker` dev 구현, persistence 어댑터(삭제는 자식→부모 순서 또는 cascade; 정지 상태 변경은 managed 엔티티 dirty-check), DGS 리졸버(codegen), 로그인 핸들러 자동 복구 보강.
- 의존성 방향(infrastructure → application → domain)은 ArchUnit으로 계속 강제.

## 결정 완료

**확정됨**:
- **탈퇴 = 본인·즉시 완전 삭제(hard delete, row delete)**. `member` + 소유 3개 테이블 행 삭제. 유예기간·익명화 없음. `member_audit_log`(비-PII)만 보존. 재가입은 행 삭제로 자연 허용(새 회원).
- **정지 = 관리자·상태만 변경·개인정보 보존**. 사유 + 선택 만료일, 만료 시 로그인 시점 자동 복구. 자동 파기 없음(유효기간제 2023-09-15 폐지 → 법정 파기 의무 없음).
- **정지/복구는 최소 admin 가드**(설정 기반). 본격 RBAC는 다음 스텝.
- **access token 인증 필터** 이 스텝에 포함(탈퇴 본인 확인 전제).
- 탈퇴·정지 시 refresh 전량 폐기. Apple revoke 포트 추상화(dev). 상태 이력은 `member_audit_log`. DB는 `member`에 정지 컬럼 3개 추가(V7). `WITHDRAWN` 상태값은 **제거**(enum 삭제 + ck 제약을 `ACTIVE`/`SUSPENDED`로 조임).

**남은 판단 없음.** 이 스텝 명세 확정.
