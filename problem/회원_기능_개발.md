# 이으리(ieuri) 회원가입 기능 명세 — Step 1: 회원가입(서버)

> 기능을 쪼개서 단계적으로 진행합니다. 이 문서는 **회원가입 서버 로직**만 다룹니다.
> 토큰/세션, 탈퇴/정지, 프로필 수정 API 등은 다음 스텝에서 별도 명세로 진행합니다.

---

## 범위 (Scope)

- **이번 스텝**: SNS 회원가입 → 약관 동의 수집 → 프로필 초기화 → 개인정보 암호화 저장 → 이메일 검증(필요 시) → 가입 이력 기록 (서버)
- **다음 스텝(별도)**: 토큰/세션 발급·로그인 유지, 탈퇴, 정지, 프로필 수정 API, Kafka 연동, 앱 측 계정삭제 UI, 발송 수단 Gmail→Resend 교체

---

## 정책 결정사항 (Decisions)

- **다계정 허용**: SNS 계정 간 매칭/통합하지 않음. google 계정과 kakao 계정은 서로 다른 회원. (계정 연동 로직 없음)
- **자체 회원가입 없음**. SNS 전용: `apple`, `google`, `kakao`
- **이메일 필수 + 자체 입력(B 방식)**: 폼에서 이메일을 반드시 받는다. provider가 준 이메일을 기본값으로 채우되 사용자가 수정 가능. provider가 이메일을 안 주면(카카오 무이메일/애플 미제공) 사용자가 직접 입력.
- **이메일 검증**: 제출된 이메일이 provider가 검증해 준 값 그대로면 검증 불필요(`email_verified=true`). 사용자가 **수정했거나 provider 미검증**이면 **6자리 코드 검증메일**을 발송하고 `email_verified=false`로 시작. (가입 자체는 검증을 기다리지 않고 완료)
- **발송 수단**: **현재는 Gmail SMTP(개발/임시)**. 도메인·Cloudflare 준비 후 **Resend로 교체 예정**. 발송 인터페이스를 추상화해 구현체만 갈아끼운다.
- **닉네임**: provider 제공값 자동 세팅.
- **만 14세 미만 가입 차단**. 법정대리인 동의 미구현.
- **주민번호 미수집**, **휴면 없음**.
- **개인정보 암호화**: 이메일 등은 AES-256로 암호화 하면 키는 application-{profile}.yml로 관리하며 추후 서버에 환경변수로 등록해서 사용할 수 있음
- **이벤트**: 지금은 Spring `ApplicationEventPublisher`. 추후 Kafka로 변경 할 수 있음

## 포함 기능 (In Scope)

1. SNS 인증 결과 검증 (apple/google/kakao의 `id_token`/사용자정보 서명·발급자·audience 검증)
2. 신규 회원 생성 — `(provider, provider_user_id)` 기준, 다계정 허용
3. 약관 동의 수집 및 **버전 포함 동의 이력** 저장
4. 프로필 초기화 (provider 닉네임/프로필 이미지 자동 세팅)
5. 이메일 필수 입력 처리 + 개인정보 암호화 저장
6. 이메일 검증 6자리 코드 발급 및 코드 메일 발송(Gmail SMTP, 필요 시) + 코드 확인 처리
7. 감사 이력 기록

## 제외 기능 (Out of Scope — 다음 스텝)

1. 자체 회원가입
2. 토큰/세션 발급, 로그인 유지, refresh
3. 탈퇴 / 정지 — *컬럼/상태값(`status`)은 미리 확보만 함*
4. 프로필 수정 API
5. Kafka 연동 (지금은 Spring `ApplicationEvent`)
6. 앱 내 계정삭제 플로우 / Apple 토큰 revoke (탈퇴 스텝에서)
7. Resend 전환 (지금은 Gmail SMTP)

## 필수 규칙 (Invariants)

1.  (같은 SNS 계정 중복 가입 불가, 다른 provider면 별도 회원 허용)
2. **필수 약관 미동의 시 가입 거부**. 선택 약관은 거부 도 이력으로 남긴다.
3. 개인정보 필드는 암호화 저장. 
4. 동의 이력은 **append-only**. 재동의 시 새 로우 추가.
5. **이메일은 필수 입력값**. 비어 있으면 가입 불가. provider 미제공 시 사용자가 직접 입력한다.
6. 약관 같은 경우 약관 테이블을 따로 만들어서 관리한다.

## 표준 약관 구성 (Standard Terms)

1. 약관은 타 사이트 약관 정책을 참고해서 k-trip-spot 관광에 특화된 약관도 적용되어야 한다.
2. 동의를 요하는 항목에서는 테이블을 서로 연관지어서 동의와 비동의 항목을 관리한다.

## 가입 & 이메일 검증 흐름

1. SNS 콜백 검증 → `(provider, provider_user_id)` 확보. **애플은 최초 인증에서만 이름/이메일이 오므로 이 시점에 즉시 저장.**
2. 폼 제출값 수집: 이메일(필수, provider값 기본 채움·수정 가능), 약관 동의, 만14세 확인.
3. 필수 약관·만14세 미충족 시 가입 거부.
4. 회원 생성 + 프로필 + 동의 이력 저장(한 트랜잭션). 이메일은 암호화 저장.
5. 이메일 검증 여부 판정:
  - 제출 이메일 == provider 검증 이메일 → `email_verified=true`, 발송 없음.
  - 그 외(수정했거나 provider 미검증) → `email_verified=false`, `email_verification`에 **6자리 코드 생성 후 코드 메일 발송**.
6. `MemberRegistered` 이벤트 기록. **가입은 검증 완료를 기다리지 않고 성공 처리**(검증은 이후 링크 클릭으로 완료).
7. 사용자가 6자리 코드 입력 → 해당 member의 활성(미검증·미만료) 코드와 대조, 실패 시 `attempts` 증가 → 성공 시 `member.email_verified=true`, `email_verification.verified_at` 기록.\n\n> **코드 방식 보안 필수사항**: 6자리는 경우의 수가 100만이라 무차별 대입에 약함. 반드시 ① 짧은 만료(5~10분) ② 시도 횟수 제한(예: 5회 초과 시 무효화·재발송 요구) ③ 단회용(성공 후 폐기) ④ 재발송 rate limit 을 건다. 검증 요청은 가입 응답으로 받은 verification 핸들(예: 검증 id) + 코드로 처리(member_id 직접 노출 금지).

## 이메일 발송 (현재 Gmail SMTP / 임시)

운영 전까지는 Gmail SMTP로 발송한다. 발송부는 인터페이스(`EmailSender`)로 추상화하고, 지금은 Gmail 구현, 나중에 Resend 구현으로 교체한다.

- Spring `spring-boot-starter-mail` 사용. 설정 예:

```yaml
spring:
  mail:
    host: smtp.gmail.com
    port: 587                     # STARTTLS. (465는 SSL)
    username: ${MAIL_USERNAME}    # 전체 Gmail 주소
    password: ${MAIL_APP_PASSWORD}# 16자리 앱 비밀번호 (2단계 인증 필요)
    properties:
      mail.smtp.auth: true
      mail.smtp.starttls.enable: true
```

- **From**은 해당 Gmail 주소가 된다(개발용). 운영에선 `noreply@ieuri.kr`로 교체.
- **한계(개발용인 이유)**: 무료 Gmail은 하루 발송 ~500통 한도, 전달력·브랜딩이 앱 서비스용으로는 부적합. 그래서 임시로만 쓰고 도메인 확보 후 Resend로 교체.
- **앱 비밀번호는 비밀값**: 암호화 키와 동일하게 취급. `prod`는 환경변수 주입, `local`은 `.env.local`(gitignore). 코드에 하드코딩·커밋 금지.

## 암호화 & 키 / 환경 분리

- **암호화 대상**: 이메일(그리고 provider 실명을 저장한다면 이름). 닉네임/프로필이미지는 표시용이라 평문.
- **비밀값 관리(암호화 키 + Gmail 앱 비밀번호 공통)**:
  - `prod`: 환경변수 주입, **기본값 없이** 선언 → 없으면 부팅 실패(fail-fast).
  - `local`: 로컬 전용 값. 운영 값과 반드시 다르게. 가능하면 `.env.local`(gitignore).
- **환경 분리**: Spring `@Profile` / `application-{profile}.yml`. 비밀값 소스만 프로파일별로, 컴포넌트는 동일 인터페이스로.
